# Autonomous Figma-to-Lumen Synthesis Protocol

> **Merge note:** this is an enhanced version of the existing `figma-to-lumen.md`. In Phase 0 of the build, merge it into the existing file, keeping any extra content the existing file has. Do not discard existing phases; reconcile them with the phases below.

Coordinates generation of Lumen-based React components, layouts and screens, and a complete Storybook, from a Figma URL using live MCP data. Entry point: skill `figma-to-react-lumen`.

Facts about tools: the names in this file such as `figma/get_node` and `lumen/get_component_specs` are **illustrative**. The real names live in `.claude/rules/figma-to-lumen.mcp-tools.md`, generated by Phase 0.

## Phase 0: Environment and tool discovery (once per repo, and again if MCP tools change)

1. List tools and resources of `figma-dev-access` and `lumen-knowledgebase`. For each tool record name, purpose, input schema and output shape in `.claude/rules/figma-to-lumen.mcp-tools.md`.
2. Map pipeline needs to tools. Needs: *file/page listing, node tree with auto-layout, component and variant info, styles, variables with modes, screenshot per frame, Code Connect mappings (if available)* on the Figma side, and *component search, component spec (props, variants, composition), tokens, layout primitives, import path, accessibility guidance* on the Lumen side. Record missing capabilities as limitations.
3. Confirm the Lumen package is installed (`node_modules`) and find where the Lumen provider/theme is mounted in the app.
4. Fill `.claude/rules/lumen-compliance.config.json` from verified facts (package prefixes, aliases).

## Phase 1: Context ingestion and inventory (agent: figma-ingestor)

1. Parse the URL with `parse-figma-url.mjs`. Use the `fileKey` and, when present, `nodeId` (API form `12:34`, not the dashed URL form).
2. Scope: with a node id, that subtree; without, every page and its top-level frames. Skip pages clearly meant for non-UI (covers, notes, archive) but record each skip with a reason.
3. For each item gather: type, name, size, auto-layout (direction, gap, padding, alignment, sizing), constraints, component/variant properties, instance → main-component links, text content, styles and **variable bindings with their modes** (for example light and dark).
4. If Code Connect or an equivalent mapping is available, record which Figma components already map to code in the repo.
5. Capture a screenshot reference per top-level frame (for the reviewer and the optional visual diff).
6. Classify each item using `.claude/patterns/figma-to-lumen-mapping.md` as `screen`, `layout`, `component` or `ignored` (reason required). Set `expected: true` for everything that must be covered.
7. Write `design-sync/<fileKey>/source-snapshot.json`.

**Gate 1:** inventory non-empty; every item classified; ignored items have reasons.

## Phase 2: Lumen schema alignment (agent: lumen-resolver)

1. Group the inventory into distinct patterns (buttons, inputs, cards, headers, navigation, lists, dialogs, layout shells...).
2. For each pattern query `lumen-knowledgebase` for the component and its variants, props, composition rules, tokens, import path and accessibility guidance. Prefer searching by the Figma component's name first, then by role.
3. Map layout (auto-layout direction, gap, padding, alignment, sizing) to Lumen layout primitives using the **exact prop names returned by MCP**.
4. Map Figma variables and styles to Lumen tokens through MCP. Never convert a hex value to a token by guessing; if a Figma variable has no verified Lumen token, record a gap.
5. Write `design-sync/<fileKey>/lumen-resolution.json`. Every component entry includes `import`, `props`, `mcpTool`, `query`. Every unresolved pattern goes in `gaps` with a reason and a suggested handling (ask designer, request Lumen addition, compose from existing primitives with reviewer sign-off).

**Gate 2:** each pattern is resolved or in `gaps`; no component entry lacks MCP evidence.

## Phase 3: Code and Storybook production (agent: lumen-builder)

1. **Reuse first:** search the repo for existing components that already implement the item (including Code Connect mappings). Reuse them; record `reusedFrom`.
2. **Components and layouts** → `src/components/<Name>/<Name>.tsx` and `src/layouts/<Name>/<Name>.tsx` (adapt to repo convention). Rules: typed functional components, explicit props interface, content and callbacks as props, only verified Lumen imports, tokens not raw values, `'use client'` only when needed, provenance header from the template.
3. **Screens** → `src/screens/<Name>/<Name>.tsx` composed from components and layouts. Do not duplicate component markup inside screens.
4. **Stories** per `standards/storybook-figma-stories.md`: one story file per component, layout and screen; one named story for every Figma variant or state; screens get a story at the designer's frame size with realistic fixture data.
5. Provide the Lumen provider/theme in Storybook (decorator in `.storybook/preview.tsx`) exactly as the app mounts it.
6. Run the compliance validator after each file; fix before moving on (the optional write-hook does this automatically).
7. Write `design-sync/<fileKey>/manifest.json`.

## Phase 4: Verification (scripts, then agent: lumen-reviewer)

1. `validate-lumen-compliance.mjs` on all generated files: zero violations.
2. `verify-manifest.mjs`: pass.
3. Repo checks with the project's scripts: typecheck, lint, Storybook build. Record each as pass, fail or not-run.
4. Visual check only if a browser test tool is already installed; else record "not run" and include a manual checklist.
5. `lumen-reviewer` re-queries Lumen MCP for a sample (at least 20% of components and every gap) and compares with the code and the Figma screenshots; writes `review.md`. It never edits source.

**Gate 4:** all of the above pass, or the iteration limit (3) is reached and a precise failure report is produced.

## Phase 5: Report

Write `design-sync/<fileKey>/REPORT.md` from `templates/REPORT.md.tpl`. Include counts, reused components, gaps with suggested follow-ups, checks run versus not run, assumptions, and the command to start Storybook.
