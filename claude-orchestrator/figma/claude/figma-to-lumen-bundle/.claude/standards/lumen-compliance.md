# Standard: Lumen compliance for generated code

Quality bar for every file generated by `figma-to-react-lumen`. Machine-checked rules are in `validate-lumen-compliance.mjs`; the rest are checked by `lumen-reviewer`.

## Machine-checked (zero tolerance)

| Rule id | Meaning |
|---|---|
| `disallowed-import` | Import from a package outside the allow-list in `lumen-compliance.config.json` |
| `unverified-lumen-import` | Lumen export with no MCP evidence in `lumen-resolution.json` |
| `wrong-lumen-import-path` | Import path differs from the MCP-reported path |
| `no-namespace-lumen-import` | `import * as X from <lumen>` |
| `unverified-lumen-prop` | JSX prop on a Lumen component not in the MCP-verified prop list |
| `no-inline-style` | `style={...}` |
| `no-hex-color`, `no-color-function` | Hardcoded colours |
| `no-hardcoded-px` | Raw pixel values in components |
| `no-any` | `any` type |
| `no-raw-interactive-element` | Raw `button`, `input`, `select`, `textarea` |
| `missing-generated-header` | No `@generated-by figma-to-react-lumen` header |

Warnings (reviewed by `lumen-reviewer`, not blocking): `raw-layout-element` (`div`/`span`), `literal-classname`, `lumen-prop-spread`, `lumen-default-import`.

Known limits: the validator is lexical. It does not understand TypeScript types, dynamic prop objects or `{...spread}` props. `tsc`, lint and the reviewer cover those.

## Reviewer-checked

1. **Composition follows Lumen guidance** from MCP (for example, required parent/child relationships, one primary action per view where Lumen says so).
2. **Accessibility:** labels for inputs, accessible names for icon-only controls, heading order, focus order, contrast taken from Lumen tokens. Prefer Lumen's built-in a11y props over custom ARIA.
3. **Tokens over values:** spacing, typography, colour, radius, elevation and breakpoints all come from Lumen. Where Figma uses variable modes (for example light/dark), the component must not hardcode one mode.
4. **Props design:** content and callbacks are props; no hardcoded business data; explicit TypeScript interface; sensible defaults; no prop drilling beyond one level.
5. **No duplicated markup:** screens compose components/layouts; no copy-paste of component internals.
6. **Next.js correctness:** add `'use client'` only if hooks, event handlers or client-only Lumen components require it; no server/client boundary violations.
7. **Naming:** PascalCase component names derived from Figma names; collisions resolved deterministically (suffix with the Figma node id's numeric part) and recorded in the manifest.

## Waivers

Allowed only as described in `.claude/rules/figma-to-lumen.md`; every waiver is listed in `REPORT.md` and challenged by the reviewer.
